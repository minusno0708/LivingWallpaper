# 公開前の確認

## ソースと履歴

- 公開用ソースには個人のアカウントへの固定リンク、連絡先、端末識別情報、会話由来の個人的な好みを含めない。
- 古い `.git`、退避ブランチ、過去の生成物をコピーしない。公開用リポジトリは整理済みのソースから新しい初期履歴を作成する。
- 作者・コミッター情報も公開対象になる。初期履歴は `Living Wallpaper Contributors` と配送されないプレースホルダー `noreply@example.invalid` を使用する。継続開発時は各開発者が公開可能な名義を設定する。
- 依存ライブラリの著作者名、ライセンス、権利表示は保持する。これらをプロジェクト利用者の個人情報と混同して削除しない。
- 認証情報、実際の設定・ログ、実行ファイル、中間ファイルをGitに含めない。
- 端末情報・個人情報を含むCodex向けMarkdownは `docs/local/` へ保存する。ディレクトリ全体を `.gitignore` で除外し、強制追加しない。CIでも追跡対象に含まれていないことを確認する。

## 配布物

`build.ps1` の出力を使用する。ソース・ユーザー領域・ツールチェーン・ビルド出力のパスをコンパイラーで置換し、EXEのUTF-8/UTF-16の文字列も確認する。通常の開発ビルド、PDB、Cargoの中間ファイルは配布しない。

この確認はコンパイラーが生成するパス等を対象にするもので、任意の秘密情報が存在しないことを保証するものではない。ソースと履歴についても別に検査する。

参考: [Rustのパス置換と制約](https://doc.rust-lang.org/rustc/remap-source-paths.html)。

## ホスティング

公開する内容と履歴を確認してから、対象リポジトリと可視性を設定する。公開用ソースの準備だけで既存リポジトリの可視性を変更しない。GitHub上では所有者アカウントがURL等に表示されるため、ソースからアカウント情報を除くこととホスト上の所有者表示は区別する。

既存の非公開リポジトリとバックアップは公開用の成果物に含めない。別マシンからは公開用の新しい履歴をcloneする。
