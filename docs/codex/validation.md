# 検証範囲

この公開用ソースでは、個人の端末構成、アカウント、元のコミットID、実行ログを持ち込まない。検証はコマンド・対象・成功/失敗・未実施項目で記録する。

## 自動テスト

- 設定値の範囲制限。
- 旧設定の読込と新設定の優先。
- マウスの接近・逃避・OFF。
- 群泳の数値の有限性、画面内保持、障害物への非侵入。
- WGSLの構文・意味検査。
- 性能測定は通常ignoreし、測定した環境以外の性能を保証する値として扱わない。

## 実機での受入確認

GPUの起動テストでは約8秒間のフレーム送信と終了を確認する。これだけでアイコンとの合成順、デスクトップ操作、実マウスや電源切替を合格としない。

確認対象は [requirements.md](requirements.md) と [development.md](development.md) を参照する。macOS、混在DPI、複数画面、他GPU、電池消費などは未検証のまま区別する。

配布には `build.ps1` の出力を使用する。ビルドスクリプトはソース・ツールチェーン・ユーザーディレクトリのパスをコンパイラーで置換し、生成されたEXEにもローカルのパスが残っていないことを確認する。

パス置換は任意の認証情報や文字列を自動的に除去する仕組みではない。ソースと履歴の秘密情報検査は別途必要。

## 高解像度の壁紙で起動時に終了する問題

`Surface::configure` が `maximum extent is 2048` でpanicする原因は、GPUの実際の能力ではなく、デバイス作成時に `Limits::downlevel_defaults()` のテクスチャ上限をそのまま要求していたこと。小さいプレビューは起動できても、2048pxを超える壁紙では失敗する。

修正では `using_resolution(adapter.limits())` で解像度上限をGPUの対応値に合わせ、他の制限は従来の保守的な値を維持する。初回のSurface設定前に実際のデバイス上限を確認し、非対応の解像度ならpanicではなく通常の起動エラーとして返す。別PCでの壁紙・トレイ表示は修正版で再確認が必要。

2026-10-31: 修正後にGNUツールチェーンで `cargo fmt --check`、`cargo test --locked`（5件成功・1件ignore）、`cargo build --release --locked` が成功。配布用のパス検査付きビルドはGitHub Actionsで別途実行する。報告元PCでの再実行、MSVCビルド、高解像度Surfaceの実機描画は未検証。
