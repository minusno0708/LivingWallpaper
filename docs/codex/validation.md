# 検証範囲

この公開用ソースでは、個人の端末構成、アカウント、元のコミットID、実行ログを持ち込まない。検証はコマンド・対象・成功/失敗・未実施項目で記録する。

## 自動テスト

- 設定値の範囲制限。
- 旧設定の読込と新設定の優先。
- マウスの接近・逃避・OFF。
- 群泳の数値の有限性、画面内保持、障害物への非侵入。
- WGSLの構文・意味検査。
- 性能測定は通常ignoreし、測定した環境以外の性能を保証する値として扱わない。

## 実機での受入確認

GPUの起動テストでは約8秒間のフレーム送信と終了を確認する。これだけでアイコンとの合成順、デスクトップ操作、実マウスや電源切替を合格としない。

確認対象は [requirements.md](requirements.md) と [development.md](development.md) を参照する。macOS、混在DPI、複数画面、他GPU、電池消費などは未検証のまま区別する。

## 配布物

配布には `build.ps1` の出力を使用する。ビルドスクリプトはソース・ツールチェーン・ユーザーディレクトリのパスをコンパイラーで置換し、生成されたEXEにもローカルのパスが残っていないことを確認する。

パス置換は任意の認証情報や文字列を自動的に除去する仕組みではない。ソースと履歴の秘密情報検査は別途必要。

- ソース中の既知の個人識別子、個人領域の実パス、端末モデル、過去の作業ID、認証情報のパターン検査で該当を検出していない。
- 開発資料の相対リンクを確認した。

- 配布EXEのUTF-8/UTF-16バイト検査で、ビルド元のユーザー領域、アカウント識別子、元の作業フォルダー名を検出していない。
- 配布物に開発資料やローカル設定を含めていない。
- RustとWGSLのアプリ実装は変更していない。GUI・実壁紙の再起動検証は行っていない。
- 新しいビルドスクリプトのMSVC CI実行は、この再構成時点では未実施。
- 端末情報・個人情報の補足は `docs/local/` に分離し、`git check-ignore` と追跡対象の一覧でGitから除外されていることを確認した。共有用の資料は `docs/codex/` に置く。

## 高解像度の壁紙で起動時に終了する問題

`Surface::configure` が `maximum extent is 2048` でpanicする原因は、GPUの実際の能力ではなく、デバイス作成時に `Limits::downlevel_defaults()` のテクスチャ上限をそのまま要求していたこと。小さいプレビューは起動できても、2048pxを超える壁紙では失敗する。

修正では `using_resolution(adapter.limits())` で解像度上限をGPUの対応値に合わせ、他の制限は従来の保守的な値を維持する。初回のSurface設定前に実際のデバイス上限を確認し、非対応の解像度ならpanicではなく通常の起動エラーとして返す。別PCでの壁紙・トレイ表示は修正版で再確認が必要。

2026-10-31: 修正後にGNUツールチェーンで `cargo fmt --check`、`cargo test --locked`（5件成功・1件ignore）、`cargo build --release --locked` が成功。配布用のパス検査付きビルドはGitHub Actionsで別途実行する。報告元PCでの再実行、MSVCビルド、高解像度Surfaceの実機描画は未検証。

## B案の描画変更（2026-10-31）

合意した抽象的なシルエットに変更。胴体は二つの円弧、尾は二つの先細り形状で描き、目と反射風の光沢を除去した。群泳ロジック・マウス・障害物制御は変更していない。GNUでテスト5件成功・性能測定1件ignore（WGSL検証を含む）。同じシミュレーションとシェーダーを使うオフスクリーンGPU描画で12秒・30fpsのH.264動画を生成し、360フレームのデコードとフレーム間の変化を確認した。実壁紙の配置やトレイ操作を収録した動画ではなく、対象PCでの操作確認は別途必要。

## シルエットの遊泳アニメーション（2026-10-31）

B案の輪郭を維持し、頭側は安定、後部ほど振幅が大きい進行波で胴体から尾をしならせる。尾の開きにも小さな周期変化を付ける。既存の速度に応じた個体ごとの位相を使い、Boidsと設定は変更しない。6頂点の板全体を傾ける方式から、フラグメントで輪郭自体を変形する方式に変更。周囲に余白を設け、変形した尾の切れを防ぐ。

WGSL検証を含む既存テスト5件成功・性能測定1件ignore。実装と同じシェーダーを使って群れ全体と拡大表示の12秒・30fps動画を生成し、360フレームのデコードとフレーム間変化を確認。拡大版は動き確認用に魚の位置を固定した描画であり、壁紙配置・実操作の動作確認ではない。

## 速度に応じたB/Dブレンド（2026-10-31）

移動速度をシェーダーへ渡し、45px/s以下でD（2回の尾振りと滑走）、85px/s以上でB（連続したしなり）、中間でsmoothstepによる混合とした。既存の速度依存位相を利用し、Boids・障害物・マウス・設定形式は変更していない。Dの1周期は位相2周分、尾振り区間55%、残り45%は輪郭を休ませる。位相と滑らかな振幅包絡により周期の境界で形が飛ばないようにする。

GNUでWGSL検証を含む既存テスト5件成功・性能測定1件ignore。比較GIFは実装と同じシェーダーを使い、35/65/110px/sの速度値を位置固定の魚へ与えるオフスクリーン描画から作成する。実際の群泳での加減速・壁紙配置・トレイ操作を示すものではない。

最終確認: GNUのReleaseビルド成功。240匹の実際の群泳ロジックと同じシェーダーから12秒・30fpsの全体動画を生成し、360フレームのデコードとフレーム間変化を確認。併せて12秒・10fpsのGIF（120フレーム）を生成・デコード確認した。利用者が全体プレビューの動きを確認し、採用した。
