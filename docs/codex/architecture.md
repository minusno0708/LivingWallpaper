# 実装構成と設計判断

現在のコードを起点に確認するための地図です。ファイル名・閾値・APIが変わった場合は更新してください。

## モジュール

| 場所 | 責務 |
|---|---|
| `src/main.rs` | winitイベントループ、コマンド受信、モデル更新、描画タイミング、マウス入力、停止、ログ・エラー表示 |
| `src/scene_time.rs` | モデルに依存しないシーン時計、時間倍率、停止と再開、小さい積分ステップへの分割 |
| `src/simulation.rs` | `SchoolModel`、`FishSchool`、位置・速度、Boids、矩形障害物、マウスの力 |
| `src/renderer.rs` | wgpu初期化、サーフェス、GPUバッファ、インスタンス描画、サーフェス再設定 |
| `src/fish.wgsl` | 魚の形、尾の曲がり、向き、色 |
| `src/background.wgsl` | 深海グラデーション、淡い拡散光、3層のマリンスノー。魚と同じパスで先に描画 |
| `src/platform.rs` | OS境界、`Command`、`Environment`、Windows以外のスタブ |
| `src/windows.rs` | 壁紙配置、アイコン矩形取得、カーソル座標変換、トレイ、単一起動、電源・セッション通知 |
| `src/settings.rs` | デフォルト値、範囲制限、JSON保存、旧設定の読込 |

## 実行の流れ

1. 単一起動を確認し、winitウィンドウを作る。通常起動では背景に配置し、プレビューでは通常ウィンドウにする。
2. wgpuと設定を初期化する。Windowsトレイは専用スレッドのメッセージループで動かし、設定ウィンドウの操作をチャネルで主ループへ渡す。
3. 更新時にカーソル・電源等を調べ、省電力または手動停止の条件を判定する。
4. 通常の壁紙モードでは約2秒ごとにアイコン矩形を取得する。
5. 実時間の更新差分を最大0.10秒に制限し、時間倍率を掛けてから最大約1/60シーン秒のサブステップに分割してモデルを更新する。背景へも同じシーン時計を渡す。
6. 魚の位置・速度・位相等をGPUへ送り、1回のインスタンス描画で表示する。
7. 上限FPSに応じて待機する。現在の実装は処理終了後に次のフレーム待ち時間を設定するため、実FPSは設定上限より低くなる。

## 座標・シミュレーション・描画

- 群泳・アイコン・マウスは壁紙ウィンドウ内の物理ピクセルで扱う。Windowsではスクリーン座標からクライアント座標へ変換する。
- Boidsの分離・整列・結合と境界回避を使う。セル幅85pxの空間ハッシュで近傍を探す。密集した最悪ケースはO(N²)。
- 85px以内の仲間が3匹未満なら、セルごとの平均位置・速度を使って遠方の群れを選び復帰する。3匹以上の集まり、2匹、単独の順で優先し、同じ分類では近いセルを選ぶ。自身は対象から除く。全体重心へ全ての群れを吸い寄せる方式ではない。
- 復帰先の位置を平均速度で0.35秒先読みし、距離に応じた目標速度と加速を与える。近傍の仲間が増えると復帰力を弱め、3匹以上で通常Boidsへ戻す。最大150px/s、加速度上限は通常600〜孤立時900px/s²。
- 遠方探索はセル要約を使うが、孤立個体数I・セル数Bに対しO(I×B)の追加探索がある。特に疎な配置では負荷を別途確認する。
- 群れ内では70px/s未満のときだけ前進方向に `(70 - 速度) × 0.04 × (1 - 孤立度)` の弱い力を加える。速い魚を減速させず、孤立時には補助を使わない。初速65px/sは維持。
- 出現位置は最初のstepでアイコン情報を使って確定する。画面端から最大95px内側の領域で、20px広げたアイコン領域とその端側ポケットを避ける。新規個体だけを最大64回の乱数候補＋20×20の候補探索で配置し、既存個体の位置は変えない。配置できない場合の探索回数は有限に保つ。
- 通常のアイコン回避は8px拡張した矩形と0.15秒先読みを使い、先読み位置が28px以内になると回避する。端側の通路を閉じるのは16px未満のみで、出現時の広めの制限を泳いでいる魚には使わない。最も近い脅威と接線方向の誘導・画面内の空き領域への補正は維持する。
- 矩形へ入り込んだ場合は、重なる回避矩形の接続領域をまとめ、その外側かつ画面内で、他の回避矩形にも入らない候補へ補正する。画面外へ押し出してからクランプし直す方法は使わない。補正方向へ速度の内向き成分を反射させる。接続領域の走査は補正が必要な場合のみで、アイコンが多い密集配置の負荷は別途確認が必要。
- シミュレーションはCPUで実行。描画はwgpu。現状のGPUバッファ容量は1000匹で、設定上限と整合させる必要がある。
- `SchoolModel::fish()` は `&[Fish]` を返す。モデル追加時はトレイト実装だけで任意形状を描けるわけではない。必要に応じて中立な描画データ・モデル識別・設定・UIも設計する。

## Windows壁紙配置

- 従来構成: `Progman` へ非公開メッセージ `0x052C` を送り、アイコンの `SHELLDLL_DefView` 背面の `WorkerW` に子ウィンドウを配置。
- 新しいraised desktop構成: `WS_EX_NOREDIRECTIONBITMAP` を検出し、`Progman` 内でアイコン層の直後へレイヤード子ウィンドウを配置。`0x052C` のパラメーター `0xD, 1` も使用。
- 変更対象はアプリ自身のウィンドウ。Explorerのアイコンウィンドウの表示・スタイルを書き換える方式にはしていない。
- `SetParent` は公開APIだが、このExplorer階層に依存する配置方法は公開仕様ではない。Windows更新、混在DPI、他の壁紙アプリ等による違いがあり得る。
- 壁紙配置が失敗したらエラーとログを出して終了。`--preview` でモデルと描画だけを確認できる。
- 壁紙ホストの消失を約2秒周期で調べる。Explorer再起動時の自動再接続は未実装で、再起動が必要。

参考: [SetParentの公式仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)、[Lively開発元の構成変更の議論](https://github.com/lively-community/lively/issues/2074)。

## アイコン取得とタイムアウト

Explorerの `SysListView32` と `LVM_GETITEMRECT` を利用する。Explorerがこのコントロールを使う前提自体は非公開で、x64同士を想定する。

公開ListViewメッセージでも他プロセスに矩形のポインターを渡すため、`OpenProcess` / `VirtualAllocEx` / `WriteProcessMemory` / `ReadProcessMemory` を使う。コード注入やスレッド生成は行わない。通常の完了時はバッファを解放する。

`SendMessageTimeoutW` がタイムアウトしても、Explorerが遅れてポインターへ書く可能性がある。この経路だけは矩形バッファの割当（要求16 byte、通常OSの1ページ分）を保持し、その実行中の追加取得を停止する。即時解放に変更しない。Explorer終了時にはOSが解放する。

取得上限は2048個。1回の読取ループは約80msに制限し、最後のメッセージはさらに最大50ms待つ。制限到達時は先頭から取得できた分だけを回避する。取得拒否・失敗時はログに残し、障害物なしで群泳を続ける。

参考: [SendMessageTimeoutWの仕様とマーシャリング](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw)。

## 省電力と設定

- 省電力ON時、AC未接続なら最大15 FPS。ロック・スリープ中、壁紙を前面の全画面ウィンドウが覆う場合はモデル更新と描画を停止する。
- 全画面判定はウィンドウ矩形による推定。部分的な遮蔽は判定しない。プレビューは全画面による停止とアイコン回避の対象外。
- 停止時の状態確認は約2Hz、トレイコマンドの受取のためイベント待機は最大100ms。CPU使用率ゼロを保証する仕組みではない。
- 設定・ログは `%LOCALAPPDATA%/LivingWallpaper/`。新設定がない場合だけ旧 `FishSchoolWallpaper/settings.json` を読む。保存は新しい場所のみで、旧設定を削除しない。
- サーフェスのLost/Outdatedは再設定、Timeoutはスキップ、OutOfMemoryは終了する。GPUデバイス自体の完全な再作成は未実装。

## OS境界

Windows以外の `platform.rs` はスタブ。通常起動の壁紙配置はエラーを返し、プレビュー経路のみ残している。macOSでは壁紙、アイコン、グローバルマウス、トレイ、電源・ロック通知が未実装で、ビルド・実行も未検証。AppKit等の別バックエンドを追加する場合もモデルと描画にOS依存を広げない。


## 静止カーソルとの接触

マウス影響ON・静止10秒以上・速度35px/s以下のとき、半径24pxの円領域を障害物とする。0.18秒の先読みによる反発と接線方向の力で事前に回避し、更新前後の線分と円の交差判定で素通りを防ぐ。接触時は外側へ補正し、速度を接線方向へ向ける。画面端やアイコンに補正先が重なる場合は32方向の円周候補から画面内で空いている側を選ぶ。実カーソルのビットマップ形状は使わず、円の半径には魚の大きさ分の余裕も含める。


## 連続操作できるトレイ設定

従来のTrackPopupMenuを廃止し、トレイの通知先ウィンドウを非モーダルな小さな設定画面として再利用する。標準BUTTON・COMBOBOX・トラックバーを使い、チェック変更・モード・匹数・FPS変更では非表示にしない。変更コマンドは従来と同じチャネルで主ループが反映・保存する。右上の×・EscはSW_HIDEのみで、HWNDとトレイは破棄しない。「アプリを終了」だけがQuitコマンドを送る。

開く際に共有設定から表示を同期する。ModelMode列挙型とALLの選択肢一覧、モデル生成関数create_modelを追加し、現在はFishのみを扱う。旧設定のmode欠落はFishに補完し、魚の数・FPSはスライダーの刻みへ正規化する。魚の数は位置1〜100を10倍、FPSは位置0〜8を0/15/30/45/60/75/90/105/120へ対応させる。ドラッグ中は数値ラベルのみ更新し、解放・キーボード操作で変更コマンドを送る。同じ値の重複送信・保存を避ける。トレイの左右クリックで開閉し、カーソルのモニターの作業領域に収める。DPIに応じてウィンドウ・標準コントロール・フォントを再配置し、IsDialogMessageでTab・Escのキーボード操作を処理する。描画用のUIフレームループや独自のタイマーは追加せず、非表示中は既存のメッセージループで待つ。


FPSが0の場合は主ループの停止条件へ含め、描画・モデル更新を止める。停止中の環境確認用の2Hz待機を使うので、FPSによる待ち時間計算に0を渡さない。設定UIとトレイは従来どおり操作可能。


手動停止はFPS=0に統一し、Pauseコマンドと常設のpaused状態は持たない。旧JSONのpaused=trueのみ読込時にfps=0へ移し、再保存時はpausedを出力しない。省電力ON時はバッテリーで実効FPSを最大15へ一時制限し、ロック・スリープ通知・対象画面を覆う前面ウィンドウで描画と群泳更新を止める。OFF時はこれらの省電力による抑制を使わないが、FPS=0と画面サイズ0による停止は独立して有効。


## Deep Glassの描画

src/windows_panel.rsで設定パネルの外観を担当する。Windows標準コントロールの値・範囲・フォーカス・Tab移動を維持し、WM_PAINT/WM_PRINTCLIENTをサブクラス化してGDIで描画する。トラックバーのマウス・矢印/Home/End/Pageキー・ホイール入力は独自処理し、標準描画との混在を防ぐ。スイッチ・丸いつまみ・数値ラベル・統一した閉じるボタンを使い、描画を二重バッファ化する。見た目は青いガラス風だが、背景デスクトップを実際にぼかすAcrylic透過は使っていない。

枠なしの独自ヘッダーはWM_NCHITTESTで移動でき、右上のボタン・Alt+F4・Escは設定を隠す。丸みと縁には公開DWM APIとリージョンを使う。UI用の常時描画ループ・アニメーションタイマー・WebViewは追加せず、OSからの再描画要求でのみ描く。フォント・ペン・ブラシ・ビットマップ・DCは使用後に解放する。


## シーン時計

SceneClockはf64の累積時間を持ち、advance(real_dt, scale, paused)からモデル更新回数とstep_dtを返す。実時間の差分を0.1秒に制限してから倍率を掛け、その後で1/60秒以下へ分割するため、2倍時でもモデル内部のdt制限で時間が欠落しない。RendererのView.timeはstart.elapsedではなくこの時計を使用する。倍率変更時に累積時間は掛け直さない。

0倍・FPS=0・省エネなどで停止した間は時計を進めず、再開直後のフレームも停止中だった差分を破棄する。マウスの速度・静止時間、トレイ、壁紙ホストの確認とアイコン取得はInstantによる実時間を使う。モデル内の速度上限150px/sはシーン秒での値なので、2倍では見かけの実時間あたりの速度も2倍になる。CPUの更新ステップ数も倍率に応じて増える。設定はモード別ではなく全体のtime_scaleとして保存し、将来のモデルも同じSchoolModel::stepの時間を受け取る。


## スライダーの再描画と追従

値ラベルのWM_SETTEXTはDefWindowProcで文字列を保持し、STATICクラスの即時描画を通さず独自描画で更新する。同じ文字列は再設定しない。トラックバーのTBM_SETPOSも標準描画を無効にして値だけ更新し、コントロール全体を無効化して二重バッファから再描画する。ドラッグ中のつまみ位置はピクセル単位、設定値は既存の刻みに丸め、解放時につまみを確定位置へ合わせる。ドラッグ中は値表示だけを更新し、解放・キャプチャ喪失時に一度だけ反映・保存する。入力状態はコントロールごとに保持し、破棄時に解放する。常時描画タイマーは使わない。

## トグルアニメーション（2026-11-01）
